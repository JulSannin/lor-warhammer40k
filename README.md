# Краткий лор Warhammer 40K

Интерактивный лендинг-таймлайн по вселенной Warhammer 40,000 — от Войны в Небесах
(~60 000 000 лет до н.э.) до Эры Индомитус (М42). 11 разделов, 51 событие,
82 изображения.

**Сайт:** https://julsannin.github.io/lor-warhammer40k/

Исходный текст: [WARHAMMER_40K_LORE.md](WARHAMMER_40K_LORE.md).

## Стек

- Vite 8 + React 19 + TypeScript
- [@tanstack/react-virtual](https://tanstack.com/virtual) — виртуализация прокрутки
- [react-loading-skeleton](https://github.com/dvtng/react-loading-skeleton) — заглушки картинок
- Чистый CSS с переменными, без UI-фреймворков. Анимации тоже на CSS:
  библиотека анимаций была убрана, она давала треть веса бандла и создавала
  до семнадцати наблюдателей на раздел

## Команды

```bash
npm install
npm run dev      # локальный сервер
npm run build    # прод-сборка в ./dist
npm run preview  # посмотреть прод-сборку
npm run lint     # oxlint
npm run format   # prettier
npm run content  # пересобрать данные из WARHAMMER_40K_LORE.md
npm run images   # докачать изображения в public/img (--force — перекачать все)
npm run wiki     # связать выделенные термины со статьями русской вики
```

`content` запускается автоматически перед `dev` и `build`, поэтому markdown
остаётся единственным источником правды: правишь текст — сайт обновляется.

## Как устроены данные

Два слоя:

- **Машинный.** [scripts/build-content.mjs](scripts/build-content.mjs) разбирает
  markdown в `src/data/content.generated.json`: абзацы, заголовки, таблицы,
  цитаты, списки и врезки «[спорно]». Файл не редактируется руками.
- **Редакторский.** [src/data/meta.ts](src/data/meta.ts) — эпохи, события лент,
  акцентные цвета. [src/data/images.ts](src/data/images.ts) — изображения.
  [src/data/index.ts](src/data/index.ts) сшивает всё и падает с ошибкой, если
  для раздела нет метаданных.

### Изображения

У каждой записи в `images.ts` есть роль и, при необходимости, режим показа:

| Поле       | Значение                                                              |
| ---------- | --------------------------------------------------------------------- |
| `role`     | `hero` — кадр в шапке раздела, `inline` — по тексту, `primarch` — портрет для галереи |
| `afterHeading` | номер подзаголовка, под которым встаёт картинка (у `inline`)       |
| `primarch` | римский номер легиона — по нему портрет находит свою строку в таблице  |
| `contain`  | показать целиком, без обрезки: карты, схемы, вертикальные портреты     |
| `plate`    | «архивный лист» — светлая подложка с рамкой для сканов на белом фоне   |
| `remote`   | ссылка, по которой файл был скачан; по ней же работает `npm run images` |

Раскладка картинок под одним подзаголовком выводится из состава группы: две
в ряд, нечётная последняя занимает ряд целиком. Группа, целиком состоящая из
вертикальных портретов, встаёт одним рядом — так собран пантеон эльдар.

Галерея примархов строится из той же таблицы легионов, что и текст: номер, имя
и судьба берутся из неё, портрет подбирается по римскому номеру. Правка лора
меняет галерею вместе с текстом. Портретов 18, а не 20: II и XI легионы стёрты
из истории, и у них рамка остаётся пустой — это часть сюжета, а не пробел
в данных.

### Справки по терминам

Термины, выделенные в лоре жирным, кликаются и открывают карточку со статьёй
русской вики: первый абзац, заглавная картинка, ссылка на полную статью.

Фрейм со страницей вики сделать нельзя — Fandom отдаёт заголовок
`X-Frame-Options: sameorigin`, и браузер отказывается её показывать. Обойти это
можно только своим прокси-сервером, а сайт статический. Поэтому
[scripts/fetch-wiki.mjs](scripts/fetch-wiki.mjs) (`npm run wiki`) снимает абзац
и картинку через API один раз при сборке и кладёт в `src/data/wiki.generated.json`.
Страница по-прежнему не делает ни одного внешнего запроса.

Кликабельно **не всё**, что выделено жирным, и это осознанно. Жирный в лоре несёт
две разные работы: где-то это термин, где-то просто акцент — «массовая гибель
разумных существ в промышленных масштабах насытила Варп эмоциями» статьи не имеет
и иметь не может. Из 230 терминов со статьями связаны 173; остальные остаются
обычным жирным, и читатель ни разу не ткнётся в пустоту. Кликабельно только первое
упоминание термина в разделе — иначе текст превращается в сеть ссылок.

Термин может вести сразу в несколько статей: «стазис-гробницы» — это и стазис,
и некроны, ни одна статья по отдельности термин не объясняет. Тогда в карточке
появляются переключатели. В `ALIASES` такие записаны массивом.

У карточек примархов справка открывается наведением и показывается рядом,
без картинки: портрет читатель и так видит перед собой.

В таблице имена примархов не кликаются — те же двадцать стоят строкой выше
в галерее, и двадцать пунктирных подчёркиваний в колонке только рябили бы.
Зато кликается колонка «Легион»: названия легионов жирным не выделены,
обычным сбором не ловятся, поэтому скрипт берёт их из таблицы отдельно.

Скрипт сам разбирается с регистром и перенаправлениями, но не со всем: падежи
(«Лемана Руса»), другое написание на вики («Асурьян» против «Азуриан») и термины,
названные вместе с пояснением, живут в таблице `ALIASES` внутри скрипта. Там же
список тех, у кого статьи нет вовсе. После правки таблицы достаточно `npm run wiki` —
скрипт заметит расхождение с кешем сам.

Каждая шестая заглавная картинка на вики нарисована на белом: фото миниатюры,
схема, герб. Такие перечислены в `LIGHT_THUMBS` и показываются целиком на светлой
подложке, а не обрезаются в тёмную рамку. Как перемерить список — описано
в комментарии рядом.

### Высоты разделов

В `src/data/index.ts` лежат три таблицы замеренных высот — под телефон, планшет
и ноутбук. Из них складывается высота документа до того, как разделы построены,
поэтому ползунок прокрутки не скачет. Таблиц три, а не одна, потому что от
ширины высота зависит сильно и не монотонно: «Крестовый поход» на телефоне выше,
чем на ноутбуке, а «Война в Небесах» — ниже.

Перемерять нужно после правки лора **и** после правки раскладки — числа колонок,
сеток, отступов. Как именно — описано в комментарии там же.

## Деплой

Пуш в `main` запускает [.github/workflows/deploy.yml](.github/workflows/deploy.yml),
который собирает проект и публикует `dist/` на GitHub Pages.

Разово нужно включить Pages: **Settings → Pages → Source: GitHub Actions**.

В `vite.config.ts` стоит `base: './'` — сборка работает под любым именем
репозитория, путь никуда не зашит. Исключение — `og:image` в `index.html`:
сборщики превью не умеют разрешать относительные пути, поэтому там абсолютный
адрес, и при переезде на другой домен его нужно поменять.

## Известное

- При изменении ширины окна с переходом в самый узкий набор высот React
  в dev-сборке печатает предупреждение `flushSync was called from inside
  a lifecycle method`. `flushSync` зовёт сама библиотека виртуализации из
  своего наблюдателя размеров. В прод-сборке предупреждения нет, на поведение
  это не влияет: положение разделов и высота документа после ресайза верные.
- По пяти из восьми богов эльдарского пантеона (Иша, Курноус, Ваул, Лилеат,
  Морай-Хег) на фан-вики нет ни одного изображения — ни на русской, ни на
  английской. Показаны трое, для которых арт существует.
